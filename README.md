# 台股大戶動向觀察站（免費 MVP）

這是一個可部署到 GitHub Pages 的靜態網頁。GitHub Actions 於台灣時間約 18:30（週一至週五）抓取公開盤後資料，更新 `data/ranking.json`，網頁讀取該 JSON 顯示每日排行。

## 目前版本的範圍與限制

- **已實作：** 證交所上市股票日行情、近5個交易日外資／投信買賣超、DMI(14)、近5日與20日報酬率、20日均線偏離、流動性與單日波動風險評分。
- **尚未實作：** 上櫃股票、集保戶股權分散表（每週）、券商分點買賣超。歷史技術指標目前僅對成交量前250檔抓取足夠日線；其餘股票的技術資料可能不足。
- 因此本工具目前是「大戶可能進場的代理訊號」，**不能辨識真實大戶，也不應將法人買賣超直接視為大戶進出**。
- 歷史成交量均值目前只對成交量較大的前 250 檔拉取；其他股票成交量比可能顯示「—」。這是為了減少對官方 API 的請求負載。
- 免費公開 API 可能調整格式、延遲或限流。行情更新排程設於台灣時間約 18:30，且成交量前 250 檔若當日歷史收盤資料已可取得，會優先使用該收盤價交叉校正。遇到上游異常時需查看 Actions 執行紀錄。

## 免費部署（約 10 分鐘）

1. 登入或註冊 GitHub。
2. 建立一個新的 **Public repository**，例如 `tw-stock-whale-tracker`。
3. 將本資料夾內的所有檔案上傳至 repository 根目錄（保留 `.github/workflows/update.yml`）。
4. 進入 **Settings → Pages**，在 Build and deployment 選 `Deploy from a branch`，Branch 選 `main`、資料夾選 `/ (root)`，儲存。
5. 進入 **Actions**，允許啟用 workflows。打開 `Update stock data`，點 `Run workflow` 手動跑第一次更新。
6. 等 workflow 成功後，網站網址通常會是 `https://你的GitHub帳號.github.io/tw-stock-whale-tracker/`。
7. 網站打開後按「重新載入」即可讀取最新排行。GitHub Pages 與 GitHub Actions 對公開 repository 的個人免費使用通常可免費使用；請以 GitHub 當下方案規則為準。

## 計分邏輯（DMI＋法人版）

總分100分：投信籌碼20分、外資籌碼15分、DMI技術訊號35分、價格位置20分、交易品質與風險10分。

- **投信20分：** 近5日連續買超、買超天數、5日累計買超相對成交量。
- **外資15分：** 近5日連續買超、買超天數、5日累計買超相對成交量。
- **DMI 35分：** +DI(14)上穿-DI(14)，交叉日算第1天、有效至交叉後第2個交易日（共3個交易日）15分；-DI最近3個交易日逐日下降10分；ADX最近3個交易日逐日下降10分。
- **價格位置20分：** 近5日報酬10分、近20日報酬6分、收盤價相對20日均線偏離4分。
- **交易品質與風險10分：** 近5日平均成交金額5分、單日波動幅度5分。
- **策略合格條件：** DMI三項條件全部成立，且近5日漲幅≤5%。總分高但未滿足這些條件的股票不會標示為策略合格。
- **分級：** 80–100「優先觀察」、65–79「持續追蹤」、0–64「一般觀察」。

分數為透明的啟發式篩選指標，並非經過回測驗證的預測模型，也不構成投資建議。若資料不足，網站會以資料完整度標記提醒；不要把缺值解讀成技術訊號已成立。

## 常見問題

**為什麼不能直接顯示「大戶買進」？**  
公開資料通常無法逐一辨識最終投資人的身份。集保資料提供持股級距的週變化，券商分點則反映該分點客戶與自營部門合計交易，不等於單一大戶。

**為什麼只有上市股票？**  
第一版優先以證交所公開 API 建立可運作的基礎版本。上櫃市場需要接入櫃買中心 API，集保週資料也需另外整合。

**資料沒更新怎麼辦？**  
到 GitHub repository → Actions → `Update stock data` 查看錯誤紀錄。也可以手動執行 workflow。API 格式若變更，需更新 `scripts/update_data.py`。
